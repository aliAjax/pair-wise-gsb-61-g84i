# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计
- `/projects/new`：建立车型、配置、维护版本和软件版本基线
- `/projects/[id]`：证据审阅、法规覆盖、状态流转、版本差异、批量补件和审计
- `/regulations`：按法规分类查看项目证据覆盖
- `/supplements`：跨项目批量补件
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线与提交包导出

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建与检查

```bash
npm run typecheck
npm run build
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。

## 基线快照与结论一致性

- **审阅结论绑定快照**：每次维护版本、软件版本或配置变更都会生成不可变基线快照（`currentSnapshotId`），证据的“已接受”结论记录其确认时的快照。
- **受影响证据失效**：基线更新后，已接受证据按变更维度判定是否受影响——维护版本变更影响全部结论；软件版本变更只影响软件版本不匹配的证据；配置变更只影响配置范围不覆盖新配置的证据。受影响证据回到“待确认”，未受影响结论继续有效并重绑到新快照；已批准/已拒绝项目自动回到审阅中。
- **按当前快照重算**：法规覆盖、批准阻断项、列表风险、证据完整度均为派生值，不信任历史存储结论。
- **重新确认硬性条件**：接受证据时软件版本必须等于项目基线、配置范围必须覆盖当前配置，否则不能接受，项目也不能批准。
- **提交包冻结**：提交/补件重交/批准时按当时快照冻结证据、法规覆盖和阻断项；历史包永久保留原样，基线更新不重算。
- **原子保存与变更草稿**：所有写入先整体改内存、再“先备份后写主”落盘，失败立即整体回滚，不会出现项目与证据各改一半；失败的基线变更保留为草稿，下次打开自动恢复表单，可重试或放弃。
- 旧版本地数据（v1）首次读取时自动迁移到快照模型。验证脚本见 `scripts/verify.ts`（`node_modules/esbuild/bin/esbuild scripts/verify.ts --bundle --platform=node --format=esm --alias:~=./ --outfile=/tmp/verify.mjs && node /tmp/verify.mjs`）。
