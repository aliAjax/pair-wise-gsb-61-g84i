# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计
- `/projects/new`：建立车型、配置、维护版本和软件版本基线
- `/projects/[id]`：证据审阅、法规覆盖、状态流转、版本差异、批量补件和审计
- `/regulations`：按法规分类查看项目证据覆盖
- `/supplements`：跨项目批量补件
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线与提交包导出

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建与检查

```bash
npm run typecheck
npm run build
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。

## 版本快照与证据有效性

- 证据的“接受”结论不再是裸状态：接受时记录 `acceptedSnapshot`（维护版本 / 软件版本 / 配置 + 版本 ID）。
- 项目基线更新（维护版本、软件版本或配置变化）会生成新版本快照：
  - 软件版本或维护版本变化：全部已接受证据失效，状态变为 `stale`（待重新确认）；
  - 仅配置变化：配置范围未覆盖新配置的证据失效；仍覆盖新配置且软件一致的证据继续有效。
- 法规覆盖、批准阻断项、列表风险与证据完整度全部按当前快照实时重算（`services/snapshot.ts`）。
- 重新确认证据时强制：配置范围覆盖当前配置、证据软件版本与项目基线相同；任一不满足都不能接受，也不能批准项目（UI 与 store 双层阻断）。
- 每次提交 / 批准会冻结一份提交包（证据、法规覆盖、阻断项、基线）；历史提交包不可变，基线再变化也保留原样。

## 保存失败与草稿

- 所有变更走整包原子提交：先在深拷贝上完成“项目字段 + 证据失效 + 版本 + 审计 + 派生重算”，再一次性写入；写入失败则丢弃候选、已提交态保持不变，不会出现项目和证据各改一半。
- 基线保存失败时表单变更写入草稿存储并保留在页面上，可直接重试或放弃；下次打开项目页会提示并恢复未成功的草稿。
- 项目编辑器提供“模拟保存失败”开关用于演示该行为。

## 业务规则验证

```bash
npm run verify
```

通过 jiti 在 Node 下运行 `scripts/verify-snapshot.ts`，对快照绑定、证据失效、覆盖重算、批准阻断、失败草稿原子性、提交包冻结和跨刷新恢复做端到端断言。
